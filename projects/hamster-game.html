Hamster Game

An arcade-style Python game built to learn game loops, sprite management, collision detection, scoring, and level progression — interactive programming fundamentals with Pygame.

Project Background

I built this game to understand how interactive software actually works — not following a step-by-step tutorial, but designing the game loop, mechanics, and state from scratch. Game programming forces you to care about frame timing, object lifecycle, and edge cases in a way no web page or script does.

What Was Built

A fully playable arcade-style game built from the ground up:

  • Game loop — fixed timestep update cycle keeping gameplay speed consistent across frame rates
  • Sprite system — custom sprite classes with update/draw lifecycles for the player, obstacles, and collectables
  • Collision detection — pixel-level hit testing between the player and obstacles, triggering game states
  • Scoring system — points awarded per level completion with persistent high-score tracking
  • Level progression — increasing speed and obstacle density across 3+ levels with end-screen transitions
  • Sound & texture — audio cues for events and sprite-based rendering

Core Game Loop

def game_loop():
    clock = pygame.time.Clock()
    state = GameState.RUNNING

    while state != GameState.QUIT:
        dt = clock.tick(60) / 1000.0   # 60 FPS, seconds

        for event in pygame.event.get():
            if event.type == pygame.QUIT:
                state = GameState.QUIT

        update(dt)      # physics, positions, collisions
        draw(screen)    # render everything
        pygame.display.flip()  # swap buffers

Tech Stack

  • Python 3 — Application logic
  • Pygame — 2D game engine and rendering
  • pygame.mixer — Sound effects and background music
  • JSON — High-score persistence across sessions

What I Learned

The biggest takeaway was how a seemingly simple task — move a character across the screen — forces you to think about frame independence, collision envelopes, and state transitions. Building three distinct levels with escalating difficulty also taught me how to structure game data so adding a new level is just a config change, not a new class.
